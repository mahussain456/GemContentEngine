Deploy via GitHub + Vercel

Push your folder to GitHub. Connect Vercel. Add thegeminfo.com. Live in under 20 minutes.
v1.0 · 2026
Overview
What you're about to do
Six steps. ~20 minutes. After this, every git push auto-deploys to thegeminfo.com.
The big picture

1. Restructure your folder so the URLs are clean (/ = landing, /app/ = the app)

2. Push to a new GitHub repo

3. Sign in to Vercel with that GitHub account → import the repo → deploy

4. Add thegeminfo.com as a custom domain in Vercel

5. Update your domain's DNS (Vercel gives you the exact records)

6. Convert og-image.svg → og-image.png and push the change

What you need before starting

  • A GitHub account (free — github.com)
  • A Vercel account (free — vercel.com — sign up with GitHub for one-click integration)
  • Git installed on your machine (git-scm.com — or use GitHub Desktop if you prefer GUI)
  • Access to your domain's DNS settings (wherever you bought thegeminfo.com)
  • Your local D:\AI_Stuff\Gem_Content_Machine folder

The folder structure you're going for

Vercel will serve this directly. No build step, no config — it just works because everything is static HTML.

gem-content-engine/ ├── index.html ← was landing.html ├── app/ │ └── index.html ← was gem.html ├── assets/ │ ├── favicon.svg │ ├── logo-mark-dark.svg │ ├── logo-mark-light.svg │ ├── logo-full-horizontal-dark.svg │ ├── logo-full-horizontal-light.svg │ ├── logo-full-stacked.svg │ ├── og-image.svg │ ├── og-image.png ← create this before launch │ ├── social-banner.svg │ └── social-avatar.svg ├── GEM-Launch-Playbook.html ├── GEM-Brand-Guide.html ├── GEM-Deploy-GitHub-Vercel.html ├── README.md └── .gitignore

Notice: landing.html becomes index.html at the root, and gem.html becomes app/index.html. That gives you the clean URLs thegeminfo.com and thegeminfo.com/app.

Step 2 · 5 minutes
Push to GitHub
Two paths: GitHub Desktop (easier) or git CLI (faster if you've used it before).

Path A — GitHub Desktop (recommended for first-timers)

1
Install GitHub Desktop

Download from desktop.github.com. Sign in with your GitHub account.

2
File → Add Local Repository

Choose D:\AI_Stuff\gem-deploy. GitHub Desktop will say "this isn't a Git repository — create one?" Click create.

3
Make your first commit

In the bottom-left, type a summary like "Initial deploy" and click Commit to main.

4
Publish to GitHub

Click Publish repository. Repo name: gem-content-engine. Description: "GEM · Six-Agent Content Engine." Keep "Keep this code private" checked — you don't need this public yet (Vercel can read private repos with your permission).

Path B — Git CLI (faster if you have it set up)

# From inside D:\AI_Stuff\gem-deploy git init git branch -M main git add . git commit -m "Initial deploy" # Create the empty repo on GitHub first (github.com/new), then: git remote add origin https://github.com/YOUR-USERNAME/gem-content-engine.git git push -u origin main
Authentication note

GitHub no longer accepts password auth on the CLI. If git push asks for credentials, use a Personal Access Token (github.com → Settings → Developer settings → Personal access tokens → Generate new token, classic, scope: repo) as your password. Or use GitHub Desktop instead.

Confirmation

Open github.com/YOUR-USERNAME/gem-content-engine — you should see your files. If you can see index.html at the top, you're done with this step.

Step 3 · 3 minutes
Connect Vercel
Sign up, import the repo, deploy. Vercel does the rest.
1
Sign up at vercel.com

Click "Continue with GitHub". Authorize Vercel to read your GitHub repos. (Choose "Only select repositories" → pick gem-content-engine for the tightest scope.)

2
"Add New…" → "Project"

Vercel shows a list of your GitHub repos. Click Import next to gem-content-engine.

3
Configure project (almost everything is auto-detected)

Vercel detects "Other" framework — perfect, no build step. Leave everything default:

  • Framework Preset: Other
  • Build Command: empty (skip)
  • Output Directory: empty (default — root)
  • Install Command: empty (skip)

Click Deploy.

4
Wait ~30 seconds

Vercel uploads, hashes, distributes globally. You'll see a confetti animation when it's live. The default URL looks like gem-content-engine-xyz.vercel.app — click it to verify.

Smoke test the live URL right now

Open the Vercel URL → confirm: (a) landing page renders, (b) "Try Demo" navigates to /app/, (c) the app launches and Demo Mode runs. If anything's broken, fix it before adding the domain — DNS changes are reversible but slow.

Auto-deploy is now wired

From now on, every time you git push to main (or commit + push from GitHub Desktop), Vercel auto-deploys within ~30 seconds. Each deploy gets its own preview URL too — useful for testing changes before they hit thegeminfo.com.

Step 4 · 5–60 minutes
Add thegeminfo.com
Vercel side first (1 min), then DNS at your registrar (5 min), then wait for propagation (5–60 min).

In Vercel

1
Project → Settings → Domains

Type thegeminfo.com → click Add. Then add www.thegeminfo.com as a second entry — Vercel auto-redirects www → root (or vice versa) based on which you mark as primary. Keep thegeminfo.com as primary.

2
Vercel shows you the DNS records to add

Two options will appear:

  • Option A — Use Vercel nameservers (cleanest, takes over the whole domain)
  • Option B — Add A and CNAME records (keep your current registrar's DNS, just point this domain)

Use Option B — it's lower-stakes and keeps your registrar in charge of email if you ever set up custom email at the domain.

At your domain registrar (where you bought thegeminfo.com)

Vercel will give you the exact records, but they're consistently:

TypeName / HostValueTTL
A@ (or blank — root)76.76.21.213600
CNAMEwwwcname.vercel-dns.com3600

Find your registrar's DNS panel (usually "Manage DNS" or "Advanced DNS"), delete any conflicting A/CNAME records on those names, add these two, save.

If your registrar uses a different naming convention

Some registrars use @ for the root, others use blank, others want the full domain typed. Some use "Host" instead of "Name". The values (76.76.21.21 and cname.vercel-dns.com) don't change — only the input field labels do. Vercel's domain-add UI shows screenshots for the popular registrars (GoDaddy, Namecheap, Cloudflare, Google Domains, Squarespace).

Wait for DNS to propagate

Anywhere from 2 minutes to 60 minutes. Vercel auto-detects when the records are live and provisions an SSL certificate within seconds of detecting them. You'll see a green checkmark next to your domain in the Vercel dashboard.

To check propagation manually: dnschecker.org → enter thegeminfo.com → choose A record. If most pins are green, you're done.

Confirmation

Open https://thegeminfo.com in a fresh tab. You should see the landing page, with HTTPS auto-enabled (green padlock). If you see Vercel's "this domain is being configured" page, give DNS another 10–20 minutes.

Step 5 · 10 minutes
Convert OG image & finalize
SVG is great for the web, but social platforms need PNG. Do this before you share any link.

Convert the OG image to PNG

Open D:\AI_Stuff\gem-deploy\assets\og-image.svg. Pick one of the three paths from the Brand Guide:

  • Figma: drag the SVG in → select → Export → 1× PNG → save as og-image.png in the same /assets folder.
  • npx (if you have Node.js): from inside gem-deploy run:
    npx svgexport assets/og-image.svg assets/og-image.png 1200:630
  • Online (no install): upload SVG to cloudconvert.com/svg-to-png, set output 1200×630, download into /assets.

Repeat for social-banner.svg (1500×500) and social-avatar.svg (400×400) when you're ready to update your X / LinkedIn profiles.

Commit and push

From inside gem-deploy:

git add assets/og-image.png git commit -m "Add OG share image" git push

Or in GitHub Desktop: type a summary, click "Commit to main", click "Push origin." Vercel auto-deploys in ~30 seconds.

Validate the share preview

Once the new commit is live:

  • OpenGraph preview: opengraph.xyz → enter https://thegeminfo.com → confirm the OG image renders correctly.
  • Twitter card validator: cards-dev.twitter.com/validator → forces Twitter to re-fetch your OG metadata. Run this before sharing on Twitter, otherwise X may cache a broken preview for days.
  • LinkedIn post inspector: linkedin.com/post-inspector → same idea for LinkedIn.

Updating the founder counter as sales come in

The counter is a single number in index.html — search for SEATS_REMAINING at the bottom of the file. After each sale, decrement, commit, push. Auto-deploys in 30 seconds.

// Before sale 1 const SEATS_REMAINING = 100; // After sale 1 const SEATS_REMAINING = 99;

When the counter hits 0 (or 5 — slight scarcity hedge), update the buy button to "Founder's Edition sold out — $29 standard" and edit the price in Gumroad to $29. The graduation script in the Launch Playbook tells you what to email past buyers.

If something breaks

  • Vercel rollback: Vercel project → Deployments → find a previous good deploy → ⋯ menu → "Promote to Production." Reverts in seconds.
  • DNS issue: Run nslookup thegeminfo.com (or use dnschecker.org). If A record isn't 76.76.21.21, your registrar didn't save. Re-check.
  • Mixed content warning (broken HTTPS): means your HTML is loading something via http://. Search the codebase for http:// and convert to https://.
  • OG image not updating: the platform cached. For X, run the validator. For LinkedIn, the inspector. For Slack, the cache lives ~24h — change the filename (og-image-v2.png) and update the meta tag to force a re-fetch.
